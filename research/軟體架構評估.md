# Windows 筆劃輸入法：軟體架構評估

日期：2026-09-16。狀態：開工前設計建議，尚未實作。

## 1. 建議結論

採用單一儲存庫、模組化 C++20 架構。執行期是小型 TSF DLL，搭配離線字庫建置工具與獨立設定程式。模組通常編成靜態函式庫，再連入 DLL／EXE，不為每一模組建立獨立 DLL，也不引入外掛框架或常駐服務。

所有自行開發的程式邏輯使用 C++。CMake 是建置描述，JSON 是設定，文字表是資料，不引入 Python 執行或建置依賴。research 中既有 Python 稽核僅為研究紀錄，正式資料驗證移植到 C++。

第一階段目標為本機 x64 Windows 的繁體單字輸入；WEASD／UIJKL 作為可設定的兩組按鍵別名，具體筆劃對應不散落於程式。正式發布前加入 x86 版本以測試 32 位元應用程式。ARM64 為未來另行編譯與驗證的目標。不在未驗證前宣稱支援所有 Windows 版本或應用程式。

## 2. 模組與依賴方向

| 模組／目標 | 責任 | 不能負責的事 |
|---|---|---|
| domain | 筆劃列舉、Unicode 碼點、命令、候選資料與設定值型別 | Windows API、檔案操作 |
| dictionary | 不可變字庫讀取、前綴查詢、來源與格式版本驗證 | 視窗、TSF、個人紀錄寫入 |
| engine | 輸入狀態機、候選去重與排序、翻頁、選字意圖 | COM、HWND、註冊表、直接提交文字 |
| win_support | RAII、字串轉換、檔案映射、設定與紀錄儲存實作 | 筆劃規則與候選策略 |
| tsf_adapter | TSF／COM 生命週期、按鍵事件、焦點、組字與提交 | 字庫轉換、候選排序算法 |
| candidate_ui | 顯示候選、游標定位、DPI、滑鼠選字 | 查字、修改組字狀態、獨立儲存候選列表 |
| dict_builder.exe | Conway 解析與展開、覆寫套用、索引輸出與驗證 | 註冊輸入法 |
| settings.exe | 設定驗證與儲存、清除學習資料、匯出診斷資訊 | 接管各應用程式的即時輸入 |
| setup.exe | 安裝／解除註冊協調、版本切換與回復 | 自行改成系統預設輸入法 |

依賴方向：

```text
TSF adapter ──→ engine ──→ dictionary ──→ domain
     │             └──────────────────→ domain
     ├──→ candidate_ui（只接收 engine 的顯示快照）
     └──→ win_support

dict_builder ──→ 字庫格式與驗證共用程式
settings     ──→ 設定型別與驗證共用程式＋win_support
```

domain、engine 與 dictionary 的公共介面不包含 windows.h、COM、HWND 或 HRESULT。用值型別傳遞命令與結果，只在可替換的字庫、儲存等邊界設小型介面；不為每一個類別建立抽象基底類。

## 3. 一次按鍵如何處理

1. TSF adapter 判斷焦點、啟用狀態、修飾鍵及是否應攔截此按鍵。測試按鍵回呼只判斷，不修改狀態，避免同一按鍵被處理兩次。
2. 按鍵設定將實體事件轉為命令：輸入某種筆劃、退格、取消、翻頁、選字等。非輸入法命令交還應用程式，保留其快捷鍵。
3. engine 更新該輸入 context 專屬的 Session，查詢不可變字庫，產出候選與顯示快照。
4. UI 呈現快照；滑鼠操作回傳命令，不自行修改 engine。
5. 選字時 engine 產生 PendingCommit，由 adapter 透過 TSF edit session 提交文字。成功回報後才清空本次組字並記錄選字；失敗時不計入學習、不盲目重送。

Session 狀態至少區分 Idle、Composing、PendingCommit。焦點切換、context 銷毀、外部結束組字及服務停用都走明確的結束路徑。延後 edit session 帶 context 身分與 session generation；過期回呼不能寫入新的輸入欄位。

## 4. 資料與查詢設計

固定目前 Conway commit，保留未修改來源及授權。另設 corrections／extra_characters／ranking_tw 資料，記錄新增、取代、移除與原因，不直接修改下載來源。資料合併優先序固定為上游、專案修正、使用者覆寫，並由工具檢查衝突。

第一版使用依筆劃序列排序的緊湊表，透過二分搜尋找出前綴範圍，再去重、排序候選。現有約 6.3 萬組配對不必一開始就引入複雜壓縮 Trie。若量測顯示短前綴太慢，再換索引實作，engine 介面不變。

共同規則：

- 查字只用 1～5 的筆劃值，與 WEASD／UIJKL 鍵位無關。
- 核心使用 char32_t／Unicode scalar value，Windows 邊界才轉 UTF-16，避免把補充平面漢字切成兩個字。
- 同一個字多個筆順命中時只呈現一次；每次排序有穩定的最後比較條件，避免候選跳動。
- 初期排序策略可採完整碼優先、個人次數、台灣基礎順位、穩定碼點順序；具體權重是可測試策略，不寫在 UI。
- 繁體篩選不能只保留上游 traditional-only 名單，共用字必須保留。區域標籤不是教育部認證。
- 候選顯示只取當頁；核心保留可取得下一頁的查詢狀態，不用 UI 畫數千個字。

正式字庫為自訂但簡單的版本化二進位檔：magic、schema version、來源 commit、資料版本、區段數量／offset／length、校驗值。欄位使用固定寬度及固定位元組序，不直接序列化 C++ struct、指標或 size_t。x64、x86 共用同一資料格式。

載入時檢查長度、整數溢位、區段範圍、碼點、筆劃值及格式相容性；失敗回報可理解的診斷，不載入損壞資料。校驗值用於偵測損壞，不當作來源驗證或數位簽章。

字庫以唯讀檔案映射讀取；查詢期間不下載、不解析原始 Conway 表，也不寫入資料。每個活動 Session 固定使用一個字庫版本，更新於安全時機切換。

## 5. Windows 與程序邊界

TSF DLL 會載入使用它的應用程式，故必須保持小而可靠。第一版採同執行緒、同步且有界的核心查詢，避免為這個小字庫建立跨程序查字服務。

- 每個 TSF 實例／context 各有狀態，不設跨應用程式的全域正在輸入字串。
- COM 物件、event sink 與視窗在對應執行緒建立與釋放；使用 RAII 管理引用與取消訂閱。
- 不在 DllMain 執行字庫載入、COM 初始化、檔案 I/O 或啟動工作執行緒。
- C++ 例外不得穿越 COM 回呼與視窗程序邊界；轉換成明確錯誤路徑。這不等於能攔截任意記憶體錯誤，仍需測試與檢查。
- 候選視窗不搶焦點，處理多螢幕、DPI、螢幕邊界與 context 移動；透過 TSF UI element 機制協調顯示，避免應用程式與自繪視窗重複呈現。
- 密碼／禁止輸入法的 context 不進行學習；不攔截安全桌面或登入畫面作為第一版目標。
- 安裝版基礎字庫放於 Program Files 的版本目錄，依 Windows 的權限模型供輸入法讀取。

AppContainer 有檔案與跨程序存取限制，不能假設所有宿主都能讀寫 LocalAppData 或連上 IPC。設定／學習存取失敗時使用內建設定與基礎排序，維持基本輸入。第一版不建立繞過限制的 broker；若未來要求所有受限宿主共用即時學習，需另做平台支援與權限設計驗證。

## 6. 設定與個人紀錄

設定與個人資料分開：

- 設定採 UTF-8 JSON，含 schema version。settings.exe 與 DLL 共用驗證規則；錯誤設定使用最近有效值或預設值。使用成熟且版本鎖定的 C++ JSON 函式庫，不自製通用 JSON parser。
- 發布設定使用臨時檔＋原子替換；鍵位與字庫設定於下一個 Idle 邊界生效，避免組字中途變換規則。
- 第一個可輸入版本只做固定排序，先驗證 TSF 核心。
- 加入學習時，儲存邊界用獨立介面。一般桌面環境可採每個 writer 獨立的追加式紀錄，背景批次寫入，合併時以事件 ID 去重；避免多個 DLL 同時改寫同一 JSON。
- 紀錄只含已成功選取的字／筆劃與次數所需資訊，不存整段宿主文章。提供停用、清除、容量限制與紀錄格式版本。
- 背景工作不持有 TSF context／UI 指標；DLL 卸載前有確定的停止與資源釋放順序。無寫入權限只停用持久化，不阻塞打字。

紀錄方案是第二階段候選，不是第一版就必須完成的基礎設施；跨程序一致性與受限宿主測試通過後才啟用。

## 7. 建置、安裝與更新

- 工具：MSVC、Windows SDK、CMake／CTest；C++20。Ninja 可選，非必要。
- domain、dictionary、engine 以靜態庫共用；DLL 對外只提供需要的 COM 匯出，不暴露 STL ABI。
- x64、Win32 各有 CMake preset／輸出目錄；安裝工具註冊對應架構的 DLL。早期先驗證 x64，發布門檻包含 x86。
- 初期 UI 用 Win32 視窗與 DirectWrite／Direct2D 原生繪製，不先加入大型 UI 框架；渲染 backend 與候選模型分開。
- 第三方依賴固定版本、保留 license；不在一般建置時取得不固定的最新分支。
- 安裝採版本目錄，避免覆寫仍被應用程式載入的 DLL 或字庫；舊程序可繼續使用舊版，新程序使用新版，待檔案未占用再清理。
- setup 明確處理註冊失敗回復、x86／x64 註冊與移除；保留個人設定與清除個人資料為不同操作。
- 透過正式 TSF／COM 註冊方式加入輸入法，不強改使用者的預設輸入法。正式對外發行再處理簽章及可追溯版本。

## 9. 測試與完成條件

1. 資料：可重現輸出、Conway 展開一致性、補充平面字、缺字報告、損壞字庫拒絕載入。有效設定與字庫版本可追溯。
2. 核心：按鍵命令序列、退格到空、取消、翻頁、候選去重、排序穩定、提交失敗不學習；用無 Windows 視窗的 C++ 測試即可執行。
3. TSF：切換輸入框／應用程式、組字被外部終止、延後提交遇到焦點變更、重複啟停、視窗關閉與 DLL 生命週期。
4. 相容性：本機記事本、Edge／Chrome、Office（安裝時）、Electron 類應用及 32 位元測試宿主；限制與通過版本逐項記錄，不用單一成功案例推論全面相容。
5. 部署：乾淨環境安裝、升級、回復、解除安裝、字庫缺失及使用者設定唯讀。
6. 效能：分別量測冷啟動、暖查詢 p50／p95／p99、短前綴最差情況、記憶體與多宿主負載。暖查詢核心 p95 < 5 ms 可作初期目標，尚未實測；不以 C++ 本身保證速度。

## 10. 分階段落地與維護收益

A. 補齊編譯工具；建立最小 TSF 骨架與 C++ 查字核心，先讓記事本能提交一個中文字。此階段就驗證最難的平台邊界，不等 UI 完整才整合。

B. 完成 Conway 建置工具、前綴查詢、鍵位命令與候選介面，固定排序，測試日常輸入流程。

C. 台灣排序、設定程式、字庫覆寫與個人學習；受限宿主功能降級。

D. x86、安裝更新、跨應用程式測試與發布整理。

未來改動範圍：改鍵位只改設定／映射；換字庫只改資料工具與輸入資料；換查詢算法只改 dictionary；改候選樣式只改 UI；修 Windows 相容性主要改 adapter。若一次改動跨所有模組，應先檢查是否破壞上述邊界。
