# 連續輸入模式

在設定中啟用「連續輸入模式」並套用。原本逐字模式不變。詞庫功能需要同時更新 DLL 與詞庫，0.6.1 尚未包含。

| 按鍵 | 行為 |
| --- | --- |
| 筆畫鍵 | 組字區顯示目前筆畫順序（一丨丿丶フ＊），確認選字前不替換成漢字 |
| 空白 | 接受目前第一候選並開始下一字，不插入空白 |
| 左／右 | 在尚未送出的字串間移動，若有未完成筆畫先接受第一候選 |
| 下 | 開啟游標右側字的候選；游標在句尾時修改最後一字 |
| 1～9 | 接受對應候選到草稿，遵循反轉選字設定 |
| Page Up／Down | 候選上一頁／下一頁 |
| Enter | 候選開啟時只接受字；否則送出整段並將游標移至句尾 |
| Backspace | 先刪目前筆畫，沒有筆畫則刪游標前一字 |
| Esc | 依序關閉候選、取消目前筆畫、取消整段草稿 |
| Shift＋字母 | 送出目前整段並加上英文字母；大小寫依 Caps Lock |

沒有草稿時，空白交給應用程式。草稿末尾重複按空白不會重複加字。輸入途中可用下鍵查看目前候選，再用數字選字。未找到候選時保留筆畫，不能直接接受；可退格修正。單段最多 256 字。

例如輸入兩筆橫畫時，組字區先顯示「一一」；按空白後才換成候選漢字。前面已暫選的字與目前筆畫都留在同一段組字底線內。重新開啟已暫選字的候選時，保留原漢字直到確認替換。

連續模式先依字頻／本地學習建立候選，接受每字後以新酷音詞庫重新組合常見詞。自動選字可能隨後面的字調整；手動選過的字固定保留。每字保存原始筆畫，之後開啟候選時重新查詢；完全離線。資料與排序方式見 [詞庫](phrases.md)。

## 實作分工

- `ContinuousSession`：獨立於 Windows 的草稿字串、每字筆畫、游標、換字與提交狀態；查字沿用 `Session`。
- TSF adapter：以 `ITfComposition` 擁有組字範圍，取得寫入鎖後更新文字／游標；透過 display attributes 提供底線。宿主決定最終呈現。
- `WriteSession`：保留同步優先、非同步退回，以及過期回呼保護。延後期間按鍵依序排隊。
- 儲存：SL4 設定旗標；現有設定升級預設關閉。成功完成整段提交才記錄各字使用次數；取消、失敗、失焦及宿主中止不學習。

焦點離開、外部編輯或宿主中止時，放棄內部草稿並保留文件已顯示文字，避免回頭覆寫外部內容。組字寫入／結束失敗時保留草稿供重試；宿主拒絕組字的控制項可關閉連續模式，使用原本逐字輸入。

## 驗證

核心測試涵蓋累積、修改、Unicode、取消、長度上限、失敗重試；模擬 TSF 宿主涵蓋組字範圍、UILess 候選、非同步連打、最終提交失敗重試、失焦、拒絕組字及外部終止。測試用隔離資料，不更動使用者設定／學習檔。

發布前仍需以新版 DLL 實測記事本、Windows 搜尋框、瀏覽器及常用聊天軟體：確認底線、左右游標、下鍵候選、選字、取消與切換焦點。模擬宿主測試不能取代實際應用程式相容性驗證。

2026-10-01 已以實際 TSF 註冊及 Windows 原生 RichEdit 驗證整串底線、左右移動、下鍵候選、數字替換與 Enter 結束底線。切換連續開關後須按「套用變更」，設定視窗會顯示尚未儲存提示。

參考新酷音的 [組字 edit session](https://github.com/chewing/windows-chewing-tsf/blob/main/tip/src/text_service/edit_session.rs) 與 [libchewing 操作文件](https://github.com/chewing/libchewing/blob/master/README.md)，比較組字區、字串游標與候選操作；本專案維持自行實作，沒有引入其程式碼。

逐字模式另提供 [聯想字](association.md)，可在設定自由選擇；連續模式不顯示逐字聯想窗。
